# ЭТАП 2: РАЗРАБОТКА БАЗОВОГО ФУНКЦИОНАЛА И НАПОЛНЕНИЕ ДАННЫХ
## Тема: Разработка защищенной ИС в сфере «Автошкола»
### Дисциплина: Технологии и методы программирования (ТиМП)

---

## 1. ВВЕДЕНИЕ

На втором этапе курсовой работы выполнена программная реализация базовой бизнес-логики информационной системы «Автошкола-Эксперт» (DriveSecure). Разработан модульный веб-интерфейс, контроллеры маршрутизации, интерактивные клиентские компоненты и сформирован массив синтетических данных объемом свыше 5000 записей в строгом соответствии с требованиями кафедры.

---

## 2. РЕАЛИЗОВАННЫЕ МОДУЛИ БИЗНЕС-ЛОГИКИ

### 2.1. Модуль «Запись на практическое вождение»
* **Инструкторы и автопарк (`/driving`):** витрина преподавателей с отображением модели автомобиля, госномера, типа трансмиссии (МКПП / АКПП), педагогического стажа и почасовой ставки. Реализована фильтрация по типу трансмиссии и максимальной стоимости.
* **Интерактивный календарь FullCalendar (`/driving/calendar`):** визуальное недельное расписание доступных слотов. При клике на свободный слот открывается модальное окно с деталями и кнопкой бронирования.
* **Контроллер бронирования (`/driving/book/<id>`):** проверка статуса слота, серверная сверка стоимости (защита от Price Tampering), привязка курсанта к занятию со статусом `booked`.
* **Кабинет инструктора (`/instructor/slots` и `/instructor/bookings`):** интерфейс добавления рабочих интервалов времени, отслеживание курсантов, отметка о проведении урока с фиксацией упражнений и автоматическим начислением практических учебных часов курсанту.

### 2.2. Модуль «Тренажер ПДД РФ»
* **Каталог билетов (`/pdd`):** сетка из 40 официальных экзаменационных билетов категорий A, B, M.
* **Режим тренировки (`/pdd/practice/<ticket_id>`):** интерактивный интерфейс пошагового решения вопросов. Проверка выбранного варианта ответа осуществляется асинхронно через JSON API (`/pdd/api/check-answer`) с мгновенной подсветкой верного (зеленый) и ошибочного (красный) ответа и выводом правового комментария из ПДД РФ.

### 2.3. Модуль «Учет внутренних экзаменов»
* **Теоретический экзамен (`/pdd/exam`):** симуляция государственного экзамена ГИБДД. Формируется выборка из 20 случайных вопросов. Запускается жесткий таймер обратного отсчета на 20 минут. Экзамен считается сданным при наличии не более 2 ошибок (верных ответов $\ge 18$).
* **Практический экзамен (`/instructor/practical-exam`):** прием экзаменатора по упражнениям автодрома и городскому маршруту. Фиксируются штрафные баллы (0..15). Сдача засчитывается при $\le 4$ штрафных баллов.
* **Электронный реестр протоколов (`/exams`):** ведомость сдачи с отображением электронных сертификатов.

### 2.4. Аналитический дашборд администратора (`/admin`)
* Сводные показатели: общее число пользователей, курсантов, инструкторов, проведенных уроков, сданных экзаменов и активных сессий.
* Интерактивные графики Chart.js:
  - Линейный график динамики проведенных уроков вождения по месяцам (сезонность);
  - Круговая диаграмма соотношения сданных и несданных экзаменов.

## 3. ВЫПОЛНЕНИЕ ТРЕБОВАНИЯ ПО СИДИРОВАНИЮ (5000+ ЗАПИСЕЙ)

Для соответствия критериям кафедры разработан скрипт `seed_db.py`, использующий библиотеку `Faker('ru_RU')`. 

Результаты сидирования базы данных:
* **Пользователей:** 113 (включая фиксированные учетные записи `owner`, `admin`, `instructor`, `student` и 100 синтетических курсантов);
* **Вопросов ПДД:** 800 (40 билетов по 20 вопросов с 4 вариантами ответов и пояснениями);
* **Слотов вождения (`DrivingSlot`):** **5 200 записей** (критерий $\ge 5000$ выполнен);
* **Бронирований вождения (`DrivingBooking`):** **4 688 записей** за период 8 месяцев;
* **Протоколов внутренних экзаменов (`InternalExam`):** **120 записей**, каждая из которых подписана цифровой подписью HMAC-SHA256 и встроена в блокчейн-цепочку;
* **Отзывов:** 30 реалистичных рецензий курсантов.
