## 2. КРИПТОГРАФИЧЕСКАЯ ЗАЩИТА ПЕРСОНАЛЬНЫХ ДАННЫХ (152-ФЗ)

### 2.1. Симметричное шифрование Fernet (AES-128-CBC + HMAC-SHA256)
Для защиты конфиденциальных сведений курсантов в состоянии покоя (at rest) используется стандарт Fernet из библиотеки `cryptography`:
* **Алгоритм шифрования:** AES с длиной ключа 128 бит в режиме сцепления блоков шифротекста (CBC);
* **Аутентификация и контроль целостности шифротекста:** HMAC с использованием хеш-функции SHA-256;
* **Случайный вектор инициализации (IV):** генерируется заново для каждой операции шифрования криптографически стойким генератором случайных чисел ОС (`os.urandom(16)`).

Шифрованию подлежат следующие поля моделей данных:
1. `users.phone` — телефон пользователя;
2. `student_profiles.passport_data` — паспортные данные курсанта (серия, номер, орган выдачи);
3. `student_profiles.medical_cert` — реквизиты водительской медицинской справки (форма 003-В/у).

### 2.2. Паттерн Transparent Property Encryption
В классах моделей `models.py` применен паттерн прозрачных дескрипторов `@property`:
```python
_phone = db.Column('phone', db.String(256), nullable=True)

@property
def phone(self):
    return decrypt_data(self._phone)

@phone.setter
def phone(self, value):
    self._phone = encrypt_data(value)
```
Разработчик бизнес-логики взаимодействует с атрибутом `user.phone` как с обычной строкой, в то время как физически в СУБД всегда сохраняется криптограмма Base64. В случае компрометации дампа базы данных злоумышленник не получает доступ к персональным данным обучающихся.

## 3. ПОДСИСТЕМА ЗАЩИТЫ РЕЗУЛЬТАТОВ ЭКЗАМЕНОВ ОТ ФАЛЬСИФИКАЦИИ

Результаты внутренних экзаменов автошколы являются основанием для выдачи свидетельства об окончании автошколы и допуска к экзаменам в ГИБДД. Попытки несанкционированной правки оценок нейтрализуются двухконтурным криптографическим механизмом.

### 3.1. Цифровая подпись протоколов HMAC-SHA256
Каждый протокол сдачи теоретического или практического экзамена подписывается системным мастер-ключом `HMAC_INTEGRITY_KEY`.
Канонический вид полезной нагрузки (payload):
$$\text{Payload} = \text{student\_id} \parallel \text{exam\_type} \parallel \text{score} \parallel \text{is\_passed} \parallel \text{passed\_at} \parallel \text{examiner\_id}$$
Цифровая подпись вычисляется по формуле:
$$\text{Signature} = \text{HMAC-SHA256}(K_{\text{master}}, \text{Payload})$$

Сверка подписи выполняется методом `hmac.compare_digest()`, работающим за константное время, что полностью исключает возможность атак по времени (Timing Attacks).

### 3.2. Блокчейн-цепочка хешей (Hash Chaining)
Для предотвращения атак типа «удаление неугодной записи» или «вставка фиктивного протокола задним числом» таблица `internal_exams` организована в виде последовательной цепочки хешей:
$$\text{RecordHash}_0 = \text{SHA256}(\text{Payload}_0 \parallel \text{GENESIS\_HASH})$$
$$\text{RecordHash}_i = \text{SHA256}(\text{Payload}_i \parallel \text{RecordHash}_{i-1}), \quad \forall i \ge 1$$

При попытке изменить оценку, дату или результат сдачи в записи с идентификатором $k$:
1. Не совпадет цифровая подпись $\text{Signature}_k$;
2. Изменится вычисленный хеш $\text{RecordHash}_k$;
3. Нарушится равенство $\text{prev\_hash}_{k+1} = \text{RecordHash}_k$ для всех последующих блоков цепочки.

### 3.3. Автоматизированный сканер целостности БД (`/admin/integrity`)
Сканер последовательно считывает весь массив экзаменов и выполняет:
1. Вычисление и сверку HMAC-подписи каждой записи;
2. Сверку значения `record_hash` с содержимым;
3. Проверку непрерывности связки `prev_hash` с предыдущим блоком.

При выявлении расхождений формируется детальный инцидент-репорт с указанием ID скомпрометированной записи, текущего содержимого и точной причины тревоги. Для демонстрации работы сканера в интерфейс встроена кнопка «Симулировать подделку в БД».

## 4. СЕССИОННАЯ БЕЗОПАСНОСТЬ И УПРАВЛЕНИЕ ТОКЕНАМИ

1. **Ограничение времени жизни сессии:** установлен жесткий таймаут `PERMANENT_SESSION_LIFETIME = timedelta(minutes=15)`.
2. **Защита cookie сессии:**
   - `SESSION_COOKIE_HTTPONLY = True` — запрет чтения cookie средствами JavaScript (нейтрализация кражи сессии через XSS);
   - `SESSION_COOKIE_SAMESITE = 'Lax'` — запрет передачи сессионных cookie в сторонних межсайтовых запросах (защита от CSRF).
3. **Реестр активных сессий в БД (`UserSession`):** при аутентификации сервер генерирует 32-байтный псевдослучайный токен `secrets.token_urlsafe(32)` с привязкой к IP-адресу и User-Agent.
4. **Принудительный отзыв сессий (Instant Revocation):** администратор в панели управления `/admin/sessions` видит всех активных пользователей и нажатием одной кнопки аннулирует скомпрометированный токен (`is_active = False`). При следующем HTTP-запросе перехватчик `@app.before_request` немедленно принудительно разлогинивает клиента.

## 5. ЗАЩИТА ОТ УЯЗВИМОСТЕЙ OWASP TOP 10

| Категория уязвимости | Механизм нейтрализации в проекте | Файл реализации |

| **A01: Broken Access Control** | Ролевой декоратор `@role_required`, проверка владения объектом (IDOR), метод `can_manage_user` | `decorators.py`, `models.py` |
| **A02: Cryptographic Failures** | Симметричное шифрование Fernet (AES-128-CBC) для ПДн, соленое хеширование паролей PBKDF2-HMAC-SHA256, HMAC-SHA256 для экзаменов | `encryption.py`, `models.py` |
| **A03: Injection (SQLi)** | Полный отказ от конкатенации строк. Использование ORM SQLAlchemy с автоматической параметризацией запросов | `models.py`, `app.py` |
| **A04: Insecure Design** | Блокчейн-цепочка контроля целостности БД, регулярный аудит, журнал событий безопасности | `integrity.py`, `app.py` |
| **A05: Security Misconfiguration** | Изоляция секретов в `.env`, отключение отладочных заголовков в production | `config.py` |
| **A07: Identification Failures** | Короткоживущие сессии (15 мин), принудительный отзыв, привязка сессий к токену в БД | `app.py` (`@before_request`) |
| **A08: Software & Data Integrity** | Сканер целостности журнала экзаменов, исключение манипуляций со стоимостью занятий (Price Tampering) | `integrity.py`, `app.py` |
| **Stored XSS** | Автоматическая санитизация входящих данных через `bleach.clean(tags=[], strip=True)` в отзывах и заметках | `app.py` |
